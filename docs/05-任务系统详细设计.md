# 05 · 任务系统详细设计

> 核心组件：队列（SQLite 持久化）+ 调度器（内存）+ Worker 池（受管子进程）。对应方案 §5.2/§5.3。

---

## 1. 组件与职责

| 组件 | 位置 | 职责 |
| --- | --- | --- |
| Store | `internal/task/store.go` | tasks/task_events/task_files 的唯一读写出口 |
| StateMachine | `internal/task/state.go` | 合法转换表 + 守卫（纯函数，可单测） |
| Scheduler | `internal/task/scheduler.go` | 拉取 due 任务、分配 worker、并发/速率控制、恢复扫描 |
| Worker | `internal/task/worker.go` | 执行单个任务生命周期（调 Engine），panic recover |
| ParentAgg | `internal/task/parent.go` | 父任务进度聚合、子任务失败计数 |
| Regulator | `internal/task/regulate.go` | 并发额度（全局+按平台）、磁盘水位闸门 |

## 2. 七态状态机（合法转换表）

```
waiting ──► parsing ──► downloading ──► post ──► done
   │           │            │            │
   │           ▼            ▼            ▼
   └────────► failed ◄──────┴────────────┘   （可重试 → 回 waiting，attempt+1）
任意非终态 ──► cancelled（幂等；cancelling 中间态见 §4）
waiting 可因 wait_reason（需登录/等待授权/磁盘检查）驻留，不算失败
```

| 转换 | 守卫条件 | 副作用 |
| --- | --- | --- |
| waiting→parsing | 获得 worker 额度；引擎可用；磁盘水位 OK | started_at=now，写事件 |
| parsing→downloading | 元信息就绪（expected_size 可为 NULL） | 记录 quality/engine_version |
| downloading→post | 传输完成（下载一结束即转入，post 期间执行后处理） | `convert_to` 非空时 post 阶段跑 ffmpeg 格式转换（mp4 优先无损 remux，编解码不兼容降级 H.264 转码；mp3 提取音轨；转换成功删源文件；失败保留源格式记 warn 事件，不推翻下载成功） |
| post→done | 产物落盘校验通过（文件存在且 size>0 或空文件明确豁免） | 写 task_files + media_files，**清 error_code/message/fix_hint**（失败过后来成功不留旧错误），触发通知 |
| *→failed | 不可恢复错误 或 attempt≥max_attempts | 写 error_code/message/fix_hint，触发通知 |
| failed→waiting | 用户重试 或 换通道重试 | attempt+1，清 error（保留历史事件） |
| downloading→waiting | **自动重试**：可重试错误码且 attempt+1<max | attempt+1，写 error_code/message（**保留可见**：重试等待期用户要在详情页看到错在哪），scheduled_at=now+退避，广播带错误字段 |
| *→cancelled | cancel_requested 且进程已退出 | finished_at=now |

不变式（单测覆盖）：终态不可再转；cancelled→任何态 禁止；failed→重试只回 waiting。

## 3. 调度算法

```
loop(每 500ms tick):
  1. 恢复扫描（仅启动后第一轮）：status IN (parsing,downloading,post) 且进程重启过
     → 按引擎能力恢复（qb/n115 查远端状态；ytdlp 检查 .part 文件）
     → 不可恢复 → waiting + wait_reason='interrupted'
  2. 拉取 due：status='waiting' AND scheduled_at<=now ORDER BY created_at
     （wait_reason 非空的等待授权任务，按授权状态由凭据中心事件激活，不轮询空转）
  3. 闸门：全局并发 < max_concurrent  AND  平台并发 < platform_cap  AND  磁盘水位正常
  4. 分配：领取任务 → 写 parsing（同事务领取，防双领：UPDATE ... WHERE id=? AND status='waiting'）
  5. worker 执行（见 §4），完成后 tick 继续
```

- 并发默认：全局 3、按平台 2（设置项，下个任务生效）。
- 磁盘水位：剩余 < 5% 或 < 1GB → 停止领取新任务，总览预警条（`system.warn` 事件）。
- 速率：下载限速为设置项（0=不限），由引擎参数或令牌桶实现。

## 4. Worker 执行与取消

```
run(task):
  ctx = context.WithCancel(global)  # cancel_requested 监听：DB 轮询 1s 或 engine 支持信号
  defer recover → 任务回 waiting + 'worker_panic' 事件（attempt+1）
  按 kind 分发：
    download  → adapter.Resolve(ctx) → adapter.Download(ctx, onProgress)
    record    → live 编排器（分段、断流重连上限 3 次）
    qb/n115   → 外部任务客户端（提交→轮询→回写状态）
  onProgress: 节流 1s 写一次 task_events(progress) + SSE 广播（禁每 chunk 写库）
取消语义：
  引擎支持中断（子进程 kill）→ 立即
  引擎不支持 → status 显示「取消中」，进程退出后落 cancelled；UI 用 cancelled 表达中间态
```

## 5. 父子任务（批量）

- 父任务 kind='download'，`parent_id IS NULL`，子任务 `parent_id=父id`。
- 父进度 = Σ子 downloaded_size / Σ子 expected_size（任一子 expected_size 为 NULL 时父显示「N/M 项，大小部分未知」）。
- 父终态规则：全部子终态 → 父 done；存在失败子 → 父 done 但带 `failed_children=N`（父卡显示并可一键重试失败项）。
- 子任务独立重试/取消，不影响父。

## 6. 持久化与恢复（方案 §5.3 落地）

每任务必记字段（docs/03 tasks 表）：config_version / source / engine / attempt / 文件位置 / 失败原因。

| 场景 | 恢复动作 |
| --- | --- |
| 进程崩溃重启 | §3.1 恢复扫描；ytdlp 任务回 waiting（wait_reason='interrupted'，如实说明「无法保证从原字节位置续传」） |
| 意图重启（/system/restart） | 优雅：停领新任务 → 运行中任务让出（<=30s）→ 恢复扫描 |
| 引擎二进制升级 | 启动自检版本号；运行中任务完成后生效，不中断存量 |
| 重复提交 | dedupe_key（sha1(kind+platform+规范化 url)）+ DB 部分唯一索引双保险 |

## 7. 重试策略

- 自动重试：attempt+1 < max_attempts（默认 3）且错误码属于可重试类（NET_TIMEOUT/HTTP_5XX/RATE_LIMITED/ENGINE_CRASH/WORKER_PANIC/ENGINE_ERROR/TIMEOUT/BOT_CHECK，`state.go RetryableErrorCodes` 为唯一来源）→ 指数退避 30s/2m/10m 后回 waiting。
- **attempt 在自动重试分支内递增**（worker.handleEngineErr）：漏递增会导致条件恒真、任务以 30s 间隔无限重试且文案恒为「第 2/3 次」（2026-10 实测回归）。
- 重试等待期（waiting+auto_retry）：error_code/error_message 保留并在 SSE 广播与 REST 中可见；`retry_scheduled` 与 `engine_error` 事件都落库；前端展示倒计时（scheduled_at）与「立即重试」。
- 不可重试类（404/Cookie 过期/平台不支持/磁盘满）→ 直接 failed + fix_hint。
- 手动重试：failed/cancelled 可重试；waiting+auto_retry 也可「立即重试」（scheduled_at 置为立即到期）；可选改道 kind（如 `{"kind":"n115"}`，115 未配置如实报 N115_UNAVAILABLE），保留原 config_version（重放一致性）。

### 7.1 错误分类表（engine.classify，唯一来源）

分类依据是**引擎退出码 + stderr 原文**，不是猜测。`classify` 是 engine 包内的唯一分类入口，
`EngineError.Detail` 保留引擎原始报错行（排障时能看到「引擎到底报了什么」，
而不是只有一句「引擎退出码 1」）。

| 错误码 | 触发条件（stderr 特征） | 可重试 | 修复建议 |
| --- | --- | --- | --- |
| `TIMEOUT` | ctx 超时（解析太慢/链接太重） | 是 | 缩小范围，稍后重试 |
| `CANCELLED` | ctx 取消（用户取消/进程被杀） | 否 | 已取消 |
| `NOT_FOUND` | `video unavailable` / `is unavailable` / `removed by the uploader` / `not found` | 否 | 检查链接 |
| `AUTH_REQUIRED` | `sign in to confirm`（年龄闸）/ `log in` / `members-only` / `private video` / `cookies` | 否 | 去平台账号页更新凭据 |
| `BOT_CHECK` | `confirm you're not a bot` | 是 | 重试；频繁则配 Cookie 或代理 |
| `ENGINE_OUTDATED` | `the page needs to be reloaded` / `unable to extract` / `nsig extraction failed` | 否 | 升级 yt-dlp |
| `FORMAT_UNAVAILABLE` | `requested format is not available` | 否 | 换清晰度 |
| `IMPERSONATION_UNAVAILABLE` | `no impersonate target is available` | 否 | 装 curl_cffi |
| `BLOCKED_BY_FINGERPRINT` | `410: gone` | 否 | 启用浏览器指纹伪装 |
| `RATE_LIMITED` | `429` / `too many requests` / `rate limit` | 是 | 稍后自动重试 |
| `NET_TIMEOUT` | `timed out` / `connection reset` / `temporary failure in name resolution` | 是 | 稍后自动重试 |
| `HTTP_5XX` | `http error 5xx` | 是 | 稍后自动重试 |
| `HTTP_4XX` | `http error 4xx` | 否 | 检查链接与权限 |
| `ENGINE_ERROR` | 兜底 | 是 | 稍后重试 |

> `BOT_CHECK` 与 `AUTH_REQUIRED` 必须分开：前者是 IP 人机验证（重试即过），
> 后者是账号问题（重试无意义，要用户更新凭据）。裸匹配 `log in` 会把
> 前者误判成后者，用户读作「必须登录才能下载」。

> `NOT_FOUND` 要同时匹配 `video unavailable` 与 `video is unavailable`：
> 只匹配前者会漏判成 `ENGINE_ERROR`（2026-10 实测）。

### 7.2 产物完整性校验与孤儿清理

- **ffprobe 校验**（post 阶段）：产物下载完成后用 ffprobe 检查媒体文件
  （`engine.ProbeFile`）。ffprobe 不可用 → 跳过（降级）；非媒体文件（图片/字幕/
  元数据）→ 跳过。发现问题只记 `probe_warn` 事件（warn 级），**不影响 done 终态**
  ——极罕见情况 ffprobe 本身不准，直接判 failed 代价过大。
- **孤儿文件清理**：引擎失败后 yt-dlp 会留下 `.part`/`.ytdl` 临时文件。
  `engine.CleanOrphanFiles` 只清**本次下载开始后新增**的临时文件
  （下载前快照比对），不碰历史文件。清理动作记 `orphan_cleaned` 事件。
- **合并产物识别**：合并场景下 Destination 行给的是**流分片**（`.f401.mp4`），
  真正的产物是 `[Merger]` 行里的合并文件——它从未出现在任何 Destination 行里。
  `parseMergedPaths` 解析合并路径，`collectFiles` 优先收合并产物，
  并按「合并产物 stem + `.f` + 数字 format_id」精确排除分片
  （靠猜文件名形状会把 `my.file.name.mp4` 误伤）。

### 7.3 凭据健康检测（两段式）

- **被动检测**（任务驱动）：任务因 `AUTH_REQUIRED` 失败且**本次确实带了该平台凭据**
  → 该平台凭据降级为 `expiring`（待确认），记 `credential_expiring` 事件。
  只降级不判死：`AUTH_REQUIRED` 也可能是内容要大会员，凭据本身好着。
  没带凭据时报 `AUTH_REQUIRED` 与用户存的凭据无关，**不动状态**。
- **主动探针**（定时）：`server/credprobe.go` 定期（`credential.probe_interval_minutes`，
  默认 60 分钟，0=关闭）用平台 API 验证 Cookie 有效性，三态语义**不可混淆**：

  | 探针结论 | 凭据状态 | 含义 |
  | --- | --- | --- |
  | `ProbeOK` | `active` | 平台确认登录态有效（可从 expired 恢复） |
  | `ProbeUnauthorized` | `expired` | 平台明确返回未登录——凭据确实失效 |
  | `ProbeUnreachable` | **保持原状** | 平台不可达（网络/平台故障）——**不是凭据的问题** |

  把网络抖动误报成「凭据失效」会让用户白跑一趟重登，因此不可达时只刷新
  `last_check_at`，不改状态。探针按平台路由（当前实现 bilibili），
  无探针实现的平台不判断、不改状态。`disabled`（用户主动停用）不探测。

### 7.4 网络异常代理自动与手工切换

**统一出口决策（`task/resolve.go`，预览与任务共用）**：

| 优先级 | 出口来源 | 说明 |
| --- | --- | --- |
| 1 | 显式 `proxy` 参数 | 预览接口的 `proxy` 入参、手工切代理重试 |
| 2 | 任务级 `tasks.proxy` | 单个任务固定的出口（迁移 `0011`） |
| 3 | 全局 `net.proxy` | 设置页配置的系统级出口 |
| 4 | 直连 | 什么都没配 |

- **预览与下载必须走同一个出口**。这是硬不变式：预览走 A、下载走 B 会让用户看到
  「预览失败但能下载」或反过来的错位（实测踩过：任务走全局代理下得好好的，
  预览却从直连开始试，等直连超时才想起切代理——而那次 deadline 已被直连耗尽，
  代理重试必然跟着一起失败）。
  解析成功后，下载用**解析实际成功的那条出口**（`usedProxy`），不允许两条路径各选各的。
- **主出口遇网络类异常 → 换备用出口重试一次**（`NET_TIMEOUT`/`TIMEOUT`/`HTTP_5XX`/
  `BOT_CHECK`/`BLOCKED_BY_FINGERPRINT` 等）。备用出口是直连：代理挂了还能退。
  平台类错误（`NOT_FOUND`/`AUTH_REQUIRED`）**不换出口**——换也没用。
- **每次尝试用全新 ctx**。前一次尝试可能已把父 ctx 的 deadline 耗尽，复用同一个 ctx
  会让第二次尝试瞬间失败——这正是「明明能下载却解析失败」的根因。
  预览单次尝试 45s（`task.PreviewResolveTimeout`），HTTP 层总时限 100s（装得下两次尝试）。
- **切换要留痕**：界面展示实际出口（走代理 / 直连）与切换说明（`route_note`），
  任务侧追补 `route_path` 并记 `proxy_switched` 事件。
- **下载阶段自动切换**：直连下载遇网络异常，自动重试分支在下次退避调度时切至全局代理
  并追补 `route_path: "直连异常 → 自动切换代理重试"`；已在用代理时不再切（切了还是同一出口）。
- **手工切换代理**：对 failed 或 auto_retry 任务调用 `POST /tasks/{id}/retry` 传
  `{"use_proxy":true}` 或自定义 `{"proxy":"..."}`，前端任务详情页有「切换代理重试」按钮。
- **连通性测试**：设置页网络分组提供「测试代理连接」入口
  （`POST /config/test-connection` with `target: "proxy"`），实时探测出口延迟与可用性。


## 8. 可观测

- 每状态变更、每次重试、每次恢复都有 task_events 记录（level=info/warn）。
- `/system/health` 暴露：队列深度、各状态计数、worker 占用、执行中子进程数、磁盘余量。
- 引擎子进程 stdout/stderr → 落 engine 日志文件（debug 级）+ 事件流（warn/error 入库）。
