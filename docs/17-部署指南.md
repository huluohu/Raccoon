# 17 · 部署指南

> 面向第一次部署 Raccoon 的读者：只用 Docker Hub 镜像把服务跑起来、配好、
> 能升级、会备份、出问题会排障。开发态构建与架构细节见 `docs/02`。

镜像：**`fooololo/raccoon-server`**（Docker Hub，双架构 linux/amd64 + linux/arm64）
版本：`1.0.0`（同时维护 `latest` 指向最新发布）

---

## 1. 镜像里有什么

| 项 | 值 | 说明 |
| --- | --- | --- |
| 应用 | raccoon 服务端 + Web 管理界面（内嵌） | 单二进制，Web 无需单独部署 |
| 下载引擎 | yt-dlp `2026.10.21`、gallery-dl `1.32.17` | 版本随镜像走，升级引擎 = 换镜像 tag |
| 后处理 | ffmpeg 5.1（合并/remux/转码/封面转换）、mutagen 1.47（mp4 元数据内嵌） | |
| TLS 指纹伪装 | curl_cffi `0.16.3` | 部分站点（PornHub 等）必需 |
| 运行用户 | 非 root（uid 1000 `raccoon`） | 挂载目录需对该用户可写 |
| 端口 | `8530`（HTTP，Web + API 同口） | |
| 数据目录 | `/data`（必需挂载） | 数据库/配置/凭据密文/日志 |
| 下载目录 | `/downloads`（镜像内 env 锁定 `RACCOON_DOWNLOAD_DIR`） | 下载的视频/音频文件，与数据目录分开挂载、分开备份 |

系统要求：任意能跑 Docker 的 x86_64 / arm64 主机（含群晖、威联通等 NAS 的 Container 套件），内存 ≥ 512MB，磁盘按你的下载量预留。

## 2. 快速开始（docker run 三分钟版）

```bash
mkdir -p /opt/raccoon/data /opt/raccoon/downloads
chown -R 1000:1000 /opt/raccoon

docker run -d \
  --name raccoon \
  --restart unless-stopped \
  --network bridge \
  -p 8530:8530 \
  -v /opt/raccoon/data:/data \
  -v /opt/raccoon/downloads:/downloads \
  -e TZ=Asia/Shanghai \
  fooololo/raccoon-server:latest

# 等约 5 秒起服务，健康检查应返回 {"status":true,...}
curl http://127.0.0.1:8530/healthz
```

> `--network bridge` 不可省（compose 里对应 `network_mode: bridge`）：
> 它让容器接入**默认网桥**。少了这一行，容器会落进 compose 自动创建的用户自定义网络，
> 端口发布走另一套转发规则——**宿主机自己 curl 得到，但别的容器（如反向代理）连宿主机
> 的映射端口会超时**。反代场景的具体症状与排查见 §6.4。

浏览器打开 `http://<主机IP>:8530`：

1. 首次访问进入**初始化向导**——创建管理员账号（用户名 + 密码），这是唯一一次不需要登录的页面；
2. 登录后进「设置 → 引擎与网络」确认引擎自检为绿；
3. 想下会员内容：进「连接」页点 **B 站扫码登录**（手机 B 站 App 扫码，Cookie 自动加密入库）；
4. 想远程提交：签发 API 令牌（设置页）配 Telegram Bot / iOS 快捷指令 / `rc` CLI / MCP（§8）。

## 3. docker compose 部署（推荐长期使用）

`docker-compose.yml`：

```yaml
services:
  raccoon:
    image: fooololo/raccoon-server:latest          # 更新 = docker compose pull && docker compose up -d
    container_name: raccoon
    network_mode: bridge                            # 反代必留：接入默认网桥，别让反代连不上（§6.4）
    ports:
      - "8530:8530"
    volumes:
      - ./data:/data            # 数据库/配置/凭据/日志（唯一必需挂载）
      - ./downloads:/downloads  # 下载文件（镜像内 env 锁定 RACCOON_DOWNLOAD_DIR=/downloads）
      # - ./media:/media        # 可选：挂已有媒体库；要用它当下载目录时设 RACCOON_DOWNLOAD_DIR=/media
    environment:
      TZ: Asia/Shanghai
      # RACCOON_DOWNLOAD_DIR: "/media"   # 换下载目录：改这里并同步挂载（env 锁定优先于设置页）
    restart: unless-stopped
```

```bash
docker compose up -d
curl http://127.0.0.1:8530/healthz
```

NAS 用户：把 `./data` 放在你常用的共享目录下即可；注意容器以 uid 1000 运行，共享目录需允许该用户写入（群晖 File Station → 该文件夹 → 权限 → 新增用户 docker/uid 1000 可写）。

NAS 上再挂反向代理（群晖/威联通的 Container 套件、Nginx Proxy Manager 等）时，两处最容易踩：

- **保留 `network_mode: bridge`**（别删），否则反代容器连宿主机的映射端口会超时 → 504（§6.4）；
- **反代上游填宿主机端口**（`ports` 左边那个，如 `6086:8530` 就填 `6086`），不是容器内的 `8530`（§6.1）。

## 4. 数据、备份与恢复

`/data` 内部结构：

| 路径 | 内容 |
| --- | --- |
| `raccoon.db`（+ -wal/-shm） | SQLite：任务/事件/凭据密文/订阅/通知/配置 |
| `keys/master.key` | 凭据加密主密钥（**和数据库一起备份**，丢了凭据全部无法解密） |
| `logs/` | 运行日志（界面「日志」页读的就是它） |

> v1.0.3 起下载文件默认在独立的 `/downloads`（不再放 `/data/downloads`）。
> 从旧版本升级的实例：`/data/downloads` 里的存量文件不受影响（媒体库索引记的是
> 绝对路径，预览/删除照常）；想让新任务写到新目录无需任何操作，存量文件可手动
> `mv /data/downloads/* /downloads/` 后按需清理。

备份（服务运行中做也安全，SQLite WAL 模式下冷备一致性够用；追求严格可先 `docker stop`）：

```bash
tar czf raccoon-backup-$(date +%F).tgz -C /opt/raccoon data          # 数据库/凭据/配置（小，建议高频）
tar czf raccoon-media-$(date +%F).tgz -C /opt/raccoon downloads      # 下载文件（大，按需低频）
```

恢复：新机装好容器 → 停容器 → 用备份覆盖 `./data` 与 `./downloads` → `docker compose up -d`。

## 5. 升级与回滚

```bash
docker compose pull          # 拉新 tag（先把 compose 里 image 的 tag 改成新版本）
docker compose up -d         # 重建容器（数据在 /data，不受影响）
```

- 数据库迁移**自动执行**且已应用迁移 checksum 防篡改；**迁移是单向的**——回滚到旧镜像可能因新列缺失报错。稳妥回滚姿势：恢复升级前的 `/data` 备份 + 旧镜像。
- `latest` 仅供体验；生产建议**钉死具体版本号**。

## 6. 反向代理与 HTTPS（暴露到公网前必读）

服务是单端口 HTTP，任何反代都能接。要点有三个：**上游地址写宿主机端口**、**SSE 实时进度流不能被缓冲**、**别缓存应用响应**。

### 6.1 上游地址：写宿主机端口，不是容器端口

`ports: "6086:8530"` 的含义是「**宿主机** 6086 → **容器内** 8530」。反代和 Raccoon 不在同一个网络命名空间里，
`8530` 只存在于容器内部，**宿主机上打不到**——反代的上游必须写宿主机那一侧：

```nginx
proxy_pass http://127.0.0.1:6086;   # 宿主机端口 6086（= ports 的左边）
```

反代自己跑在 Docker 里时（常见于 NAS 上共用的 Nginx Proxy Manager / openresty 容器），
`127.0.0.1` 指的是**反代容器自己**，要改成宿主机的局域网 IP（如 `192.168.31.91`）——前提是
Raccoon 容器用了 `network_mode: bridge`（见 §6.4）。

### 6.2 SSE 与缓存设置

```nginx
location / {
    proxy_pass http://127.0.0.1:8530;   # 按你的端口映射改
    proxy_http_version 1.1;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;            # SSE 关键：否则前端一直转圈
    proxy_cache off;                # 别缓存应用响应
    proxy_read_timeout 3600s;       # 长连接（下载进度持续推送）
    proxy_send_timeout 3600s;
}
```

- **SSE 不能被缓冲**：Raccoon 的实时进度走 `/api/v1/events`（SSE）。反代开了缓冲，事件会被攒着不发，
  页面表现为「进度条不动 / 一直转圈」。Nginx Proxy Manager 里对应「高级选项 → 自定义配置」。
- **别给应用开响应缓存**：SPA 首页和带会话的 `/api/v1/*` 响应被缓存后，可能把一个用户的页面
  发给另一个用户。Nginx Proxy Manager 里对应「缓存资源」——**关掉**。

Caddy（自动 HTTPS，最省事）：

```
raccoon.example.com {
    reverse_proxy 127.0.0.1:8530
}
```

安全底线：

- 公网暴露必须走 HTTPS；
- 管理员密码用强口令；API 令牌按用途给最小 scope（只读场景 scope=1）；
- 不需要远程就别暴露：绑定 `127.0.0.1:8530:8530` 只让反代/本机访问。

### 6.3 Nginx Proxy Manager（NAS 上共用反代的典型配置）

| 字段 | 填什么 |
| --- | --- |
| 域名 | 你的域名，如 `raccoon.example.com` |
| 协议 | `http`（上游是明文 HTTP，TLS 由反代终止） |
| 转发主机名 / IP | **宿主机的局域网 IP**（反代在容器里时不能写 `127.0.0.1`） |
| 转发端口 | **宿主机端口**（`ports` 的左边，如 `6086`） |
| 缓存资源 | **关闭** |
| Websockets 支持 | 开启 |
| 强制 SSL | 开启（证书可用 Let's Encrypt） |
| 高级选项 | 追加 §6.2 的 `proxy_buffering off;` 等三行 |

### 6.4 打不开时怎么查（504 / 502 的含义）

反代返回的状态码直接指向病因：

| 状态码 | 含义 | 多半是 |
| --- | --- | --- |
| **502** | 反代连上游被拒（连接失败） | 上游地址/端口写错，或服务没起 |
| **504** | 反代等上游超时（包被丢弃，连不上） | 反代在容器里 + 上游写成宿主机 LAN IP，而 Raccoon 容器**没加 `network_mode: bridge`** |
| 200 但页面转圈 | 事件流被缓冲 | 缺 `proxy_buffering off`（§6.2） |

四步定位（把 `<proxy>` 换成反代容器名）：

```bash
# 1) 容器里的应用是否健康（应用层没问题）
docker exec raccoon curl -s -m 5 localhost:8530/healthz

# 2) 宿主机上的映射端口是否通（宿主机侧没问题）
curl -s -m 5 http://127.0.0.1:6086/healthz        # 端口按你的映射改

# 3) 反代容器能否访问宿主机端口（这一步挂 → 就是 504 的原因）
docker exec <proxy> curl -sv -m 5 http://<宿主机IP>:6086/healthz

# 4) 容器实际的网络模式（应输出 bridge）
docker inspect raccoon --format '{{.HostConfig.NetworkMode}}'
```

第 3 步超时、第 4 步不是 `bridge` → 就是它：给 compose 补上 `network_mode: bridge`
（docker run 则加 `--network bridge`），然后**重建容器**——网络模式改了 `docker compose up -d`
不会作用到已存在的容器，必须 `--force-recreate`：

```bash
docker compose up -d --force-recreate
```

## 7. 环境变量与配置的关系

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `RACCOON_DATA_DIR` | `/data` | 一般不用动 |
| `RACCOON_DOWNLOAD_DIR` | `/downloads`（镜像内已设） | 下载目录；换路径需同步改挂载 |
| `RACCOON_AUTH_DISABLED` | `false` | **免登录模式**：开启后打开即用（无登录页/向导），任何能访问 8530 的人都有全部权限——只限隔离内网 |
| `RACCOON_SERVER_ADDR` | `:8530` | 监听地址 |
| `RACCOON_LOG_LEVEL` | `info` | `debug`/`info`/`warn`/`error` |

环境变量会**锁定**同名配置项（设置页只读并标注来源）——用 compose/环境注入做「运维级约束」、用设置页做「用户级偏好」，两层不打架。

## 9. 健康检查与排障

```bash
curl http://127.0.0.1:8530/healthz   # {"status":true} = DB/磁盘都正常
docker logs raccoon --tail 100        # 启动失败/引擎自检结果都在这
```

| 症状 | 先查 |
| --- | --- |
| 起不来、`permission denied` 写 /data | 挂载目录属主是否允许 uid 1000 写（§3 NAS 注） |
| 端口冲突 | `8530` 被占：改映射 `-p 18530:8530` |
| 反代 504（超时打不开） | 反代容器连不上宿主机的映射端口：容器少了 `network_mode: bridge`（§6.4 四步定位） |
| 反代 502（连接被拒） | 反代上游写成了容器端口或服务没起：上游要写**宿主机端口**（§6.1） |
| 全部解析失败 | 引擎过旧（YouTube 等站点改版）：升级到最新镜像 tag |
| 会员内容报 AUTH_REQUIRED | 「连接」页凭据过期：B 站重新扫码 / 更新 Cookie |
| 媒体流超时（NET_TIMEOUT） | 站点媒体 CDN 被墙/被限：设置页配 `net.proxy` |
| 实时进度不动（转圈） | 反代没关缓冲（§6.2），或看 `docker logs raccoon | grep SSE` |
| 换端口/改网络后行为没变 | `docker compose up -d` 不会改已存在容器的端口与网络，要 `--force-recreate` |
| 磁盘预警停领新任务 | 清理空间；`healthz` 的 disk_used_pct 可接监控 |

## 10. 从源码构建 / 自发布

```bash
# 本地构建（当前平台）
make docker-build VERSION=1.0.0

# 双架构构建并推 Docker Hub（需先 docker login）
make docker-release VERSION=1.0.0 HUB_NS=<你的账号>

# 或者走 GitHub Actions（推荐，测试全绿才出镜像）：
#   git tag v1.0.1 && git push --tags
# → release.yml 自动：后端/前端/设计门禁 → amd64+arm64 构建 →
#   同步推 Docker Hub（fooololo/raccoon-server）与 GHCR，latest 一并更新。
```

引擎版本（yt-dlp / gallery-dl / curl_cffi / mutagen）钉在 Dockerfile 的 ARG 里；
升级引擎 = 改 ARG + 换 tag 重新发布，`docker-compose.yml`（仓库内）里的 args
注释有同步提醒。
