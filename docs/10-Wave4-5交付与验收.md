## 3. 分项交付与证据

### 3.1 引擎层：gallery-dl + NCM + 按形态路由

- `internal/engine/gallerydl.go`：图片/图集站点适配器（小红书/X/Instagram/Pixiv 等），
  `PROGRESS|total|now|speed|eta` 行解析，total=0 时 Percent=-1（禁估算）。
- `internal/engine/netease.go`：NCM 容器解密（纯 Go，AES-128-ECB + XOR 0x8000，
  与 ncmdump 同源算法），往返测试锁定。
- `internal/engine/routing.go` + `engine.go`：`EngineFor` 从"恒返回 yt-dlp"改为
  按 URL 内容形态路由（图片站 → GalleryDL，视频站 → YTDLP），音乐平台标识路由。

### 3.7 安全收口（W5.4）

攻击面与结论：

| 攻击面 | 用例 | 结果 |
|--------|------|------|
| SSRF（回环/云元数据/非 HTTP 协议） | `ssrf_test.go` | ✅ 全拒；`ValidateOutboundURL` 已接入 testConnection |
| 路径穿越（`..`/绝对路径/NUL/组合） | `safejoin_test.go` ×2 | ✅ 全拒 |
| 符号链接逃逸 | 同上 | ✅ 修复后拒绝（见下） |
| SQL 注入（13 类 payload） | `injection_test.go` | ✅ 0 越权、表完好 |
| Token scope 越权 | `authz_test.go` | ✅ 修复后拒绝（见下） |
| CSRF | `csrf_test.go` | ✅ 与 docs/04 一致 |

修复的生产缺陷（测试暴露 → 生产修复 → 回归全绿）：

1. **P1 scope 越权**：`requiredScope` 的 GET 短路排在管理域检查之前，只读令牌可
   GET /api/v1/tokens 枚举全部令牌元数据。修复：管理域前缀检查前置。
2. **P1 软链逃逸**：`SafeJoin` 对"不存在的产物路径"直接 EvalSymlinks 报 ENOENT
   跳过校验——而 SafeJoin 的主用途正是计算未存在路径。修复：最长存在祖先解析 +
   尾部成分逐个 Lstat + 悬空软链读 Readlink。
3. **P2 搜索 500 + 通配符转义失效**：超长关键词触发 SQLite
   `LIKE pattern too complex`；`escapeLike` 只转义但 SQL 无 `ESCAPE` 子句
   （搜 "100%" 反 0 命中）。修复：截断 256 + `ESCAPE '\'`。

诊断包脱敏：token/密码/密钥类配置不回传明文（设置页回读掩码），
日志经 logx 脱敏；115 客户端错误响应体截断 512B 且不含 token。

## 5. 升级迁移与回滚（W5.2）

**迁移机制**（`internal/store/store.go` `Migrate()`）：
- 迁移文件 `migrations/NNNN_name.up.sql` 嵌入二进制（`//go:embed`）；
- `schema_migrations` 表记录 version + checksum，每个迁移一个事务；
- **已应用但 checksum 不符 → 拒绝启动**（防半迁移/篡改）；
- 迁移只增不改：回滚 = 换回旧镜像 tag，旧二进制不认新 migration 也不会跑它。

**升级步骤**：
1. 备份：停容器（或利用 SQLite WAL 一致性）→ `cp -r data data.bak-$(date +%F)`；
2. 拉新镜像 tag → `docker compose up -d` → 启动时自动应用新 migration（日志可见"数据库就绪"）；
3. 验证：`/healthz` status=true + 前端主链路。

**回滚步骤**：换回旧镜像 tag 重启；schema 若已被新 migration 改动（只增列/建表场景），
旧二进制忽略新列即可运行；若新迁移含破坏性变更，从 `data.bak-*` 恢复。
（破坏性迁移策略：当前 4 个迁移均为增量，无破坏性变更。）

**真实演练状态**：机制与步骤如上；本环境未做"升级→换回旧镜像"的完整实机演练
（单用户自托管工具，数据目录即备份），列为 §6 已知限制。
