## 2. 范围定义

### 2.1 In scope（首发）

Docker 服务端 + 响应式 Web 管理界面（唯一主入口）：下载中心、自动订阅（B 站）、直播录制、磁力/种子（qBittorrent）/115 调度、媒体库与后处理、多入口（Web / Telegram / HTTP API+CLI）。

### 2.2 Out of scope（明确不做）

| 不做项 | 原因 |
| --- | --- |
| 应用内付费 / 激活校验 / 设备数限制 | 产品原则（§1.3 用户掌握数据） |
| 原生 NAS 套件、独立手机/桌面客户端 | 列为后续包装交付，不与 Server 能力混淆 |
| 微服务 / Redis / Kubernetes | 首版选型边界（§4.2） |
| 自造视频解析引擎 | yt-dlp 等成熟工具受管子进程调用 |
| 微信入口 | 接入方式需先核实（§13.2），不承诺登录协议与不封号 |
| 宿主机 Docker socket 挂载 | 重启改为容器编排职责（§7.1） |

## 3. 六大模块行为契约

> 契约格式：场景 → 输入 → 输出 → 异常/错误 → 验收标准。所有模块共用同一任务系统与同一份配置中心。

### 3.1 下载中心 📥

| 场景 | 输入 | 输出 | 异常/错误 | 验收标准 |
| --- | --- | --- | --- | --- |
| 粘贴链接提交 | 一个或多个 URL（多行自动拆行去重）、magnet、.torrent 文件 | 任务入队，行内显示平台徽章；重复提交提示「队列中已存在」 | URL 非法 → 行内标注不解析入队 | 提交后列表立即出现新任务并高亮定位 |
| 解析预览 | 已入队待确认任务 | 封面/标题/作者/时长/可选质量（带大小，未知显「未知」）/建议保存位置 | 平台不支持 → 任务转失败并给出原因，不静默跳过 | 预览卡字段与引擎输出一致；大小未知不显示估算值 |
| 质量与位置选择 | 质量项、保存路径（默认按命名规则） | 配置固化到任务的「配置版本」快照 | 路径不存在或不可写 → 保存前校验拦截 | 任务运行中改全局配置不影响已运行任务 |
| 批量任务 | 播放列表/频道/图集 URL | 父任务 + 子任务树，父任务聚合整体进度 | 局部失败 → 子任务单独失败，父任务显示「N 项失败」 | 父卡显示整体进度与失败项一键重试 |
| 下载执行 | 任务 + 配置版本 | 进度（百分比/速度/剩余）、落盘文件 | 引擎失败 → 失败原因 + 可执行修复（如「Cookie 已过期 → 去连接页更新」） | 进度数据来自引擎真实输出，不伪造 |
| 取消 / 重试 | 任务 ID | 取消可从任意非终态进入；重试保留原配置版本 | 引擎不支持取消 → 状态显示「取消中」直至进程退出 | 取消后任务不再占用并发额度 |
| 暂停/续传 | 任务 ID | 仅引擎支持时提供 | 不支持 → 界面说明原因，不显示暂停按钮 | 如实标注，无假按钮 |
| 产物格式 | `convert_to`：源格式（默认）/ MP4 / MP3 | post 阶段 ffmpeg 处理：MP4 优先无损 remux（不兼容才 H.264 转码）、MP3 提取音轨；转换成功删源文件 | ffmpeg 不可用或转换失败 → 保留源格式 + warn 事件，任务照常完成 | 转换语义诚实：失败不冒充成功、不推翻下载成果 |
| B 站扫码登录 | 手机 B 站 App 扫码 | 登录 Cookie 直接加密入凭据中心（kind=session），无需手动抄 Cookie | 二维码过期 → 一键重取；B 站接口不可达 → 如实报错 | 全程凭据明文不落前端、不进剪贴板 |
| 免登录高画质 | 无凭据时的任意平台链接 | 同分辨率下取**码率最高**的流（`--format-sort res,fps,br,size`）；镜像内置 JS 运行时（quickjs-ng）解锁 YouTube 完整 player client 集 | 站点未提供更高码率 → 取该分辨率下可得的最优流，不静默降档 | 免登录 1080p 实测拿到 h264 2.63Mbps（而非 yt-dlp 默认的 av01 604kbps），产物与预览显示的体积一致 |

> **免登录高画质的口径（2026-10-29 实测定位）**：「不登录也能下到好画质」在
> 浣熊里由三件事共同决定，缺一不可：
>
> 1. **同分辨率取码率最高**——yt-dlp 自带排序把 `vcodec` 排在 `br` 之前且偏好
>    AV1，同为 1080p 会选中 604kbps 的 av01 流而跳过 2629kbps 的 avc1 流
>    （B 站实测：21MB vs 75MB，画质差 4 倍）。浣熊显式指定排序修掉这一条。
> 2. **JS 运行时**——yt-dlp 无 JS 运行时时 YouTube 退化成单个 player client
>    （`_DEFAULT_JSLESS_CLIENTS = ('visionos',)`），有运行时则是三个
>    （`tv_samsung`/`visionos`/`web`）。client 少 → 格式池小 → 匿名拿不到高画质。
>    镜像内置 quickjs-ng（2MB；deno 需 91MB）。
> 3. **TLS 指纹伪装可用性探测**——缺 curl_cffi 时**绝不能**加 `--impersonate`
>    （否则 yt-dlp 直接报错退出，全站不可用）。探测判据是「存在一个真正可用的
>    target」，不能只看输出里有没有 "curl_cffi" 字样（缺依赖时它照样列出来、
>    且标着 `(unavailable)`、退出码还是 0）。
>
> 以上三条**都与登录态无关**——不配置任何平台凭据也能拿到该站公开可得的高画质。

> **会员内容的边界（诚实声明）**：会员/付费内容在平台服务端要求登录态，
> 「完全不登录下载会员内容」不存在合规实现；DRM 加密内容（Netflix、
> 优酷/腾讯/爱奇艺大部分 VIP 剧）即使有会员凭据也无法下载（yt-dlp 不解 DRM）。
> 浣熊的立场：把登录成本压到最低（扫码即用、Cookie 加密托管、过期一键检测），
> 但不破解、不绕过付费墙。

### 3.2 自动订阅 🔔

| 场景 | 输入 | 输出 | 异常/错误 | 验收标准 |
| --- | --- | --- | --- | --- |

### 3.4 磁力、种子与存储调度 🧲

| 场景 | 输入 | 输出 | 异常/错误 | 验收标准 |
| --- | --- | --- | --- | --- |

## 4. 任务状态机契约（七态）

| 状态 | 进入条件 | 退出条件 | 界面表达 |
| --- | --- | --- | --- |
| 等待 waiting | 入队 / 并发已满 / 需登录等待授权 | 获得执行额度；或因授权失败转失败 | 状态 + 等待原因（如「需登录，去连接页更新 Cookie」） |
| 解析 parsing | 开始拉取元信息 | 元信息就绪 → 下载；解析失败 → 失败 | 不确定进度用条纹动画 + 「解析中，大小未知」 |
|  downloading | 开始传输 | 完成 → 后处理；失败 → 失败；取消 → 取消 | 百分比/速度/剩余时间 |
| 后处理 post | 下载完成且有后处理项 | 完成 → 完成；失败 → 失败 | 三色进度条映射 |
| 完成 done | 文件落盘校验通过 | 终态 | 眨眼表情 + 文件位置 |
| 失败 failed | 任一阶段不可恢复错误 | 可重试 | 平嘴表情 + 原因 + 修复建议 + 重试按钮 |
| 取消 cancelled | 用户从任意非终态取消 | 终态 | 「行，不搬了。任务已撤」 |

不变式：

- 等待原因（需登录/等待授权/磁盘检查）不占用「失败」状态。
- 每个任务记录：配置版本、来源、引擎、尝试次数、文件位置、失败原因（附录 A）。
- 取消必须是幂等的：重复取消返回当前状态，不报错。

## 5. 全局验收口径（交付定义为「完成」的前提）

1. 任意入口提交的任务进入同一队列、同一状态机（无第二任务系统）。
2. 失败展示真实原因与可执行修复；Cookie 过期可一键跳转连接页。
3. 大小未知显「未知」；不支持暂停的任务无暂停按钮。
4. 批量任务父卡显示整体进度与失败项，可一键重试失败项。
5. 删除任务记录与删除文件是两个操作，均二次确认。
6. 设置项带生效时机标识；保存结果与实际行为一致（可回查服务日志）。
7. 环境变量锁定项只读且标注来源变量名。
8. qB / 115 不可用时仅相关任务失败，应用其他功能可用。
9. 键盘可完成「添加任务 → 查看详情 → 重试失败」全流程。
10. 375px 宽度下关键按钮不被遮挡；列表转卡片、详情全屏。
11. 进程退出后重启：未完成任务可识别，按引擎能力恢复或重新尝试。
12. 升级前备份数据库；迁移不能假设换回旧镜像即可回退。
